## 1. 制作の軸

**コンセプト：千葉の夜に、ほどける。**

黒いボックス席、赤茶色のテーブル、暖かい照明、赤い結び飾り。提供された店内写真から拾った色と素材を起点に、夜の落ち着きと、乾杯・会話・カラオケの親しみやすさを両立させる。

ヒーローではシルクのひだと琥珀色の光を使ったイメージ写真で世界観を伝え、続くセクションで実際の店内を大きく見せる。料金、営業時間、アクセス、連絡方法を順に確認できる構成にする。

華美な宮殿、架空の高級内装、砂漠などの店名だけから連想した装飾は使わない。実写にある店の表情と、ロゴのラクダをブランドの固有要素として扱う。

### 訪問者の行動

1. ファーストビューで店名と雰囲気を知る。
2. 実際の店内写真で過ごす場所を想像する。
3. 基本料金・追加料金・税の条件を確認する。
4. 電話またはLINEで来店について問い合わせる。
5. 所在地と外観写真を見て来店する。

主導線は「電話する」「LINEで問い合わせる」。予約受付の詳細は未確認のため、自動で予約が確定するような表現はしない。

### 文字と余白

- 見出し・短いコピー：日本語の明朝系。線が細すぎないウェイト。
- 本文・営業時間・メニュー：読みやすいゴシック系。
- 金額・時間：数字の幅をそろえ、比較しやすく右寄せする。
- 本文はPC 16px前後、スマートフォンも基本16px。注記は14px以上を目安にする。
- PCは写真を大きく広げる章と、読み幅を絞った料金の章を交互に配置する。
- 見出しは英語のみとせず、日本語で内容を識別できるようにする。
- PCの章間は100〜160px、スマートフォンは64〜88pxを初期値として調整する。

### 固有の造形

- ヒーロー画像内のシルクの流れを、次の写真に視線を導く斜めの構図として使う。
- 実際の市松模様の床は、アクセス付近の細い罫線や小さな境界にだけ引用する。
- 赤い結び飾りの色を、写真キャプションの短い線に取り入れる。
- 公式ロゴは暖かな白地の小さなプレートとして見せる。元のラクダと文字の比率を保つ。
- 同じ角丸カードを繰り返さず、「全面写真→横長情報帯→写真の組み合わせ→紙面風の料金表→連続写真→アクセス」と画面の密度を変える。

## 6. GSAP・Lenisの動作設計

| 場所 | 演出 | 初期値・制約 |
| --- | --- | --- |
| 初回ヒーロー | 背景を軽く引き、ロゴとコピーを順に表示 | scale 1.025→1、約1.2秒。ロゴとコピーは0.6〜0.8秒。待機用ローダーを置かない |
| ヒーローから店内へ | 写真がゆっくり移動して次の空間へ接続 | PCのみ20〜40px程度の移動。画面を長く固定しない |
| 店内写真 | 下から少し現れる | opacityとtranslateY 16〜24px、0.7〜0.9秒 |
| 見出し・短文 | 行のまとまりで表示 | 0.5〜0.7秒。日本語を一文字ずつばらまかない |
| 料金表 | 表全体を穏やかに表示 | 価格のカウントアップをしない。到達時すぐ読める |
| メニュー展開 | 内容を開閉 | 0.2〜0.3秒。展開後にスクロール位置計算を更新 |
| 写真リンク・ボタン | 色・下線・小さな矢印の変化 | hover可能な端末で0.15〜0.25秒。操作対象が動きすぎない |
| 固定連絡導線 | 背景と罫線を静かに切り替え | 初期から操作でき、スクロール時に消して追わせない |

### Lenisの役割

- PCのホイール操作に軽い補間を加える。初期候補はduration 0.9〜1.1秒、過度な慣性は避ける。
- GSAPのtickerと同期し、ScrollTriggerの更新につなぐ。autoRafとの二重ループを作らない。
- スマートフォンは基本のタッチスクロールを維持し、syncTouchは使わない。
- モーダル表示中は背景側のスクロールを止め、閉じたら元の位置に戻る。
- アンカー移動は固定ヘッダーの高さを考慮する。
- prefers-reduced-motion時はLenisの補間・パララックス・大きな移動を止める。
- gsap.matchMedia()で画面幅と動きの設定を分岐し、再初期化時の重複登録を防ぐ。

### 動作の基本条件

- 重要な情報は初期HTMLに含め、JavaScriptに失敗しても読める状態を基本にする。
- reveal対象を全件CSSで不可視にしない。初期化が成功した対象だけを動かす。
- オート再生カルーセル、強制横スクロール、音楽自動再生、スクロールを止める長い演出は使わない。
- 固定ヘッダー、モーダル、スマートフォンの固定連絡バーを、パララックス対象の変形コンテナ内に置かない。
- 動かすプロパティは主にtransformとopacity。画像表示後や開閉後の必要なタイミングでScrollTriggerの計算を更新。

## 7. スマートフォン・操作設計

- 360〜430px幅を主軸に、320px、768px、1024px、1440pxでも確認する。
- 画面下の固定バーは「電話」「LINE」の2項目。44px以上の押しやすい領域とセーフエリアを確保。
- 本文とフッターには固定バーぶんの下余白を設ける。
- ヒーローは中央やや右のグラスを残してトリミング。スマートフォンのobject-positionは64% 50%を初期候補とし、縦画面でロゴと重なる場合は専用の縦画像を追加生成する。
- 写真2枚の重なりはモバイルで解除し、表示順を保って縦にする。
- 表は項目と金額の2列を基本にし、長い注記は同じ行の下へ。横スクロールを必須にしない。
- 画像拡大はキーボードでも操作できるdialogを想定。閉じるボタン、Esc、フォーカス復帰を実装。
- 金額やリンクを暗い写真に直接重ねない。フォーカス表示と通常本文のコントラストを確認。

計画作成は進められるが、次の項目は公開する情報の確定時に確認する。

1. メニュー参考画像の料金・女性半額条件が現行のものか。
2. 瓶ビールの1,000円／2,000円の適用条件。
3. 「消費税（千円未満四捨五入）」の意図と、LPに掲載する会計表記。
4. 「30ボックス」の意味。席数・人数に読み替えない。
5. 周年・季節イベント写真の使用範囲と、必要なキャプション。
6. 公開先URL。

## 12. 実装時の確認項目と進め方

1. この計画と生成画像をもとに、全面ヒーローと実写店内・料金表までを組み、全体の視覚的な強弱を確定。
2. メニュー全文・アクセス・連絡導線・モバイルレイアウトを実装。
3. 静的状態で全情報を読めることを確認してから、GSAP・Lenisを追加。
4. Astroビルド、実機幅での表示、固定バーの重なり、画像のトリミング、キーボード操作、動きを減らす設定、電話・LINE・Instagram・地図リンクを確認。
